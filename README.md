# House Map & Issue Tracker

Sketch a house floor by floor, name the rooms, pin photos where they were taken, and tag issues at the exact spot they occur with a running repair list and cost ranges.

## Run it

Open `index.html` in Chrome or Edge. There is no install and no server; everything runs in the page.

If you prefer a local address, run `python serve.py` and open http://localhost:8765. Use that rather than `python -m http.server`, which lets the browser keep running old copies of the files after they change.

The app works inside a project folder that you pick, which needs the browser's folder access (Chrome and Edge on a computer). In other browsers, and on phones and tablets, the project is kept in the browser's private storage instead, so the photos never appear in a normal folder.

## Hosted and installed

The app is hosted at **https://drelok.github.io/housemap/**, served by GitHub Pages straight from this repository; there is nothing to build, and the same files work from any static web host. From a hosted address the app can also be installed, which gives it its own window and icon and lets it open with no connection:

- **Edge or Chrome on a computer:** open the address and choose *Install* from the address bar or the browser's menu (*Apps* → *Install this site as an app* in Edge).
- **iPhone or iPad:** open the address in Safari, press *Share*, then *Add to Home Screen*.
- **Android:** open the address in Chrome and choose *Install app* or *Add to Home screen* from the menu.

An installed copy checks for a newer version each time it is opened with a connection, and falls back to the copy it kept when there is none.

**What the page can reach.** In Chrome and Edge the app asks for one folder, and the browser limits it to that folder: it cannot read anything else on the computer, and the browser refuses system folders. The page carries a security policy that only runs scripts from the app's own files and blocks it from making network requests, which closes the usual ways for a plan or a photo to be sent anywhere. It is a second line of defence, not a guarantee, and it does not protect against the hosting account itself being taken over, so keep two-step sign-in on it; anyone who would rather not depend on a host can download the files and open `index.html` as above.

**Phones and tablets.** A project made on a phone lives inside that browser, on that device. The app asks the browser to keep it, but clearing the browser's site data, or removing the installed app on an iPhone, deletes it. *File* → *Export project (.zip)* is the copy to keep, and the way to move a project to a computer: see *Moving a project* below.

## Project folder

Each house is one folder. *New project* asks for the house name, the number of floors and whether there is a basement, then sets this up in the folder you choose:

```
plan.housemap.json            the plan (saved automatically as you work)
plan.housemap.json.bak        a second copy of the plan, written after each save
reference/
  aerial.jpg                  satellite or aerial picture of the lot, if you add one
quotes/                       quotes from tradespeople, attached to issues
photos/
  unprocessed/                photos waiting to be placed
  processed/
    main-floor/
      kitchen/
        kitchen-01.jpg        placed photos, renamed after their room
      unassigned/             placed on the floor but not inside a room
    exterior-site/
      exterior/               placed on the exterior sheet, not on a structure
```

The plan is only written when something has changed. Each save writes the plan and then the `.bak` copy, one after the other, so if the browser is closed part way through a save one of the two is still whole. Opening a project whose plan is missing or cannot be read restores it from the copy and says so.

*Open project folder* opens a folder that already holds a `*.housemap.json` file. The start page lists the projects you have opened in this browser.

To delete a project, press the trash button at the bottom of the start page and choose the project. After a confirmation that has to be ticked, the app permanently deletes the plan file and the `photos` and `reference` folders, then removes the project folder itself if nothing else is left in it. Other files in the folder are never touched. Deleted files do not go to the Recycle Bin.

## How it works

- **Sheets:** a plan has an *Exterior / Site* sheet followed by one sheet per floor. Draw the outline of the house on the exterior sheet; it shows as a dashed underlay on every floor.
- **Scale:** every sheet uses the same measurements, in feet, so the outline and the rooms line up. Grid squares are 1 ft when zoomed in and become 10 ft, then 100 ft, as you zoom out, with every fifth line darker and every tenth line bold and labelled with its distance. Floors open at room scale (1 ft squares) and the exterior sheet opens at lot scale (10 ft squares). The squares are the same size on every screen: a tablet or phone shows less of the sheet rather than smaller squares. Corners snap to half a foot, or line up with a nearby corner of a shape that is already drawn (a pink dashed line shows which one). Hold Alt to snap to the grid only.
- **Aerial view:** the exterior sheet has a small window in the corner for a satellite or aerial picture of the lot (a screenshot from a map site works). The picture is copied into `reference/` and also shown under the grid. *Set scale…* sizes it, along with anything already drawn on the sheet: click the two ends of a straight line you know the length of, such as one wall of the house, and type the real distance. A line follows the pointer from the first click, and Shift keeps it level or upright. After that the picture is true to the grid and the outline can be traced over it with *Polygon*. Untick *Show under the grid* to hide it.
- **True size:** a selected shape shows the length of each wall. There are two ways to correct one, for two different problems.
  - *Set one wall's length…* (any sheet) is for a wall that is off by a fixed amount, typically an outline traced along the roof edge, which sits a few feet outside the walls. It is also how a room with jogs and closets is brought to its taped sizes one wall at a time. Click the wall, type its length and choose which end moves: one end or the other (the end nearer your click starts out chosen), or both by the same amount. Only that shape changes. The wall joined to a moving end slides along with it; the end that stays keeps every wall beyond it exactly as it was.
  - *Resize everything from a wall…* (exterior sheet) is for a wrong scale, where longer walls are off by more. Click a wall and type its real length, and every shape, the aerial picture, photo markers and issue pins are resized by the same amount. *Set scale…* on the aerial picture does the same from any two points. For a wall that runs straight across or straight up the sheet, the dialog also offers to stretch in that one direction only. Use that for a second wall when walls running the other way are already right: it corrects a picture that was not taken from straight overhead, which is squashed in one direction.

  To tell which you have, compare two or three walls with their labels. The same error on each (a 22 ft wall and a 38 ft wall both about 6 ft over) means the outline is outside the walls. An error that grows with the wall means the scale is off. An aerial picture shows the roof, whose eaves overhang the walls, so measure whichever line you traced. The side panel carries these *Measuring tips*. Until you tick *The outline is true to size*, or resize from a wall, every floor shows a warning, because floors are not resized along with the exterior.
- **Tips:** the first time a project's exterior sheet opens, a window lists what to get right before drawing: start from a part of the building you have taped and work outward, use the aerial picture to see where things sit rather than to measure, check walls as you go, keep porches, garages and carports as separate structures, and confirm the size before drawing rooms. The first time a floor opens, a second window covers drawing rooms. *Tips for this sheet* under the **?** button in the toolbar brings back the one for the current sheet. The tips can be turned off for new projects in the settings.
- **Rooms and walls:** on a floor, a room is the clear space inside it, from wall face to wall face, which is what a tape measure reads. Walls are the gaps left between rooms and between a room and the exterior outline.
- **House standards:** the first time a floor opens, the app asks for the exterior and interior wall thickness, the width of an interior door, an open doorway and an exterior door, and the ceiling height. Typical values are filled in (6", 4 1/2", 30", 32", 36" and 8'). *House standards…* in the side panel changes them later; that only affects what is drawn afterwards.
- **Wall gaps:** while a room is drawn, moved or resized on a floor, its edges catch one interior wall's thickness from the other rooms and one exterior wall's thickness inside the outline. A pink bar across the gap shows the wall and its thickness. Rooms can still be lined up edge to edge, and Alt places an edge freely, for a wall that is thicker than standard.
- **Doors and openings:** on a floor, choose *Door* (`D`) and click a wall: the gap between two rooms, or between a room and the outline. Its type is read from what is around it: an exterior door on an outside wall, a bifold door where one side is a closet, *No wall* where the two rooms meet edge to edge, and otherwise an interior door, at the standard width and opening into the room that was clicked. With it selected, the side panel sets its type (interior door, open doorway, exterior door), its width, the wall thickness at that spot, the hinge side and the swing. Choosing a type sets that type's standard width. Drag it to slide it along its wall. Doors do not follow a room that is moved afterwards.
- **Closets:** draw a closet as its own small room, named *Closet*, a wall's thickness from the room it opens into, rather than as a bump on that room's shape. That leaves a wall between the two for its door. Place the door with *Door* and set the type to *Bifold door* or *Sliding doors*. A bifold starts at the standard door width; sliding doors start at twice that, cut down to the width of the closet if it is narrower.
- **Splitting off a closet:** for a closet that was drawn as a bump on its room, select the room and press *Split off a closet…*. Click one end of the closet's opening, on the edge of the room, then click across the opening; the cut runs level or upright to the far side. The smaller piece becomes a room named *Closet* that belongs to the first, and its side of the cut moves back by one interior wall so there is a wall for the door.
- **Belongs to:** a room's *Belongs to* box ties it to another room on the same floor, as a closet to its bedroom. Lists show it as `Bedroom 2 · Closet`, and the bedroom's side panel gives the area of the two together. A room counts as a closet, for the purpose of choosing a new door's type, if it belongs to another room or has "closet" in its name.
- **Walls between touching rooms:** with nothing selected on a floor, *Put walls between touching rooms…* finds every place where two rooms meet edge to edge, or a room sits on the exterior outline, and after a confirmation moves the walls back: the line where two rooms meet becomes the middle of a standard interior wall, so each room loses half a wall on that side, and a room on the outline moves in by an exterior wall. Rooms joined by a *No wall* or *Half wall* marking stay touching, so mark those first. Room sizes change, so check them against a tape afterwards.
- **Open rooms and half walls:** two rooms with no wall between them, such as a kitchen that opens into a family room, are drawn as two rooms meeting edge to edge. Click the line between them with *Door* and set the type to *No wall*: the solid line is replaced by a faint dotted one over the whole stretch the two rooms share. *Half wall* marks a low wall the same way, as a grey band. Either can be shortened by typing a width, slid along the line, and stretched back with *Fit to the shared wall*. A wall thickness of 0 means the rooms touch.
- **Stairs:** on a floor, choose *Stairs* (`S`) and click where they are. They start as one straight flight 3' wide and 10' long, drawn with treads and an arrow that runs from the end you step on to the far end, labelled `UP` or `DN`. The side panel sets the width, the length, whether they go up or down, and *Leads to*, the floor at the other end; choosing that floor also sets up or down from the order of the sheets. *Add a turn left* and *Add a turn right* put a square landing at the far end with another flight leading off it, to the left or right of the way you are walking, so an L-shaped stair is one turn and a U-shaped one is two. Each stretch then has its own length, measured down the middle of the stairs from an end or the middle of a landing to the next. Two turns close together leave one wide landing between them. With the stairs selected, a round handle sits on each end and each turn: drag one to move it, and the flights on either side catch when they come out level, upright or square to the next flight (Alt places it freely), so stairs can run at any angle. *Remove the last turn* takes one away, *Swap the ends* reverses the arrow, and *Quarter turn* turns the whole staircase. Once they lead somewhere, a round button with an up or down triangle sits in the middle of the stairs: click it to go to that floor, looking at the same spot. When you choose the floor they lead to and that floor has no stairs leading back, the app asks whether to draw them there too: answering yes puts the same stairs on the other floor, in the same place and at the same size, leading back. *Add these stairs to…*, just under *Leads to*, does the same later. Changes made to one afterwards are not copied to the other. Stairs are drawn underneath everything they overlap, rooms included, so a closet, a door or a fixture drawn over part of a staircase stays visible and can be clicked; selecting the stairs brings them to the top while they are worked on. Where stairs lie under a room, a click picks whichever of the two is smaller, so stairs standing in a hallway are picked through it. With *Door*, a click on the end or side of a staircase places a door there, so a door can stand at the top or bottom of the stairs or between them and the wall they run up to.
- **Room names:** a room's name and size are written over the fixtures, stairs and doors in it, with a pale edge round the letters so they read against whatever is underneath.
- **Fixtures:** on a floor, choose *Fixture* (`F`) and click where one stands. It appears as a dashed box with a question mark, and the side panel lists what it can be: toilet, bathroom sink, bathtub, shower, kitchen sink, counter or island, stove, refrigerator, dishwasher, washer, dryer, water heater, furnace. Each is drawn as a plan symbol at a usual size. The side panel changes its type, width and depth, and holds a note. Drag it to move it; its corners line up with the corners of rooms and of other fixtures (Alt places it freely), and one large enough on screen has corner handles to resize it. It can be turned to any angle: drag the round yellow handle in front of it, which catches on the directions the walls of the rooms run in and on every 15 degrees (Alt turns it freely, a degree at a time), type the angle, or press *Quarter turn*. *Back against the nearest wall* turns it to back onto the wall nearest its middle, at whatever angle that wall is drawn, and pushes it up against it. Counters are drawn underneath the other fixtures, so a run of counter can be one long box with the sink and stove set on it. Like doors, fixtures and stairs do not follow a room that is moved afterwards.
- **Floor levels:** a sunken or raised room stays on its floor's sheet. Select it and set *Floor level* to lower or higher, with the height of the step. The room is labelled, for example `8" down`, and any door or opening between two rooms at different levels is drawn with a dashed step line and its height. The side panel notes a step taller than 7 3/4", the most the current residential code allows.
- **Feet and inches:** lengths are shown as feet and inches to the nearest quarter inch (14' 5 3/4"), and wherever you type one (a room's width and length, *Set scale…* and the two wall tools) there is a box for feet and a box for inches. The inches box takes fractions or decimals: `5 3/4`, `5-3/4` and `5.75` all mean the same. Anything finer is rounded to the nearest quarter, and a note beside each of these boxes says so. In the two dialogs both start at 0. The plan file stores the same lengths in inches.
- **Undo:** *Undo* and *Redo* in the toolbar, or Ctrl+Z and Ctrl+Y, step back and forward through up to 100 changes: drawing, moving, resizing, combining, deleting, renaming and so on. History starts again when a photo is attached to or removed from a marker, a marker with a photo is deleted, or the aerial picture is added or removed, because those move files on disk. It also starts again each time a project is opened.
- **Saved:** a note beside the project's name reads *Saving…* while a change is being written and *Saved* once it is on disk, or *Not saved* if the write failed.
- **View menu:** *View* in the toolbar shows or hides room names, fixtures and stairs, photo markers, issue pins, and the exterior outline under the floors. Nothing hidden is changed. The button reads *View: 2 hidden* while anything is off, and everything is shown again the next time the project is opened. Selecting something from a list, or placing a new one, turns its kind back on.
- **Guide bar:** the strip under the plan shows what the current tool expects on the left. On the right it shows the size of whatever you are drawing, the pointer position in feet, the current grid square size and the snap.
- **Tools:** *Rooms* in the toolbar opens *Rectangle* and *Polygon*; *Placeables* (floors only) opens *Door*, *Stairs* and *Fixture*. The button shows which of its tools is in use. Every tool has a key that picks it directly: `V` select, `R` rectangle, `P` polygon, `D` door, `S` stairs, `F` fixture, `I` issue, `C` photo, `M` measure. *Measure* reads the distance between any two points you click, on the picture or the plan, and changes nothing; use it to check the plan against a tape measure. `Esc` returns to select and `Delete` removes the selection.
- **Locking:** tick *Locked in place* on a room or outline once it is right. It can still be selected, and changed in the side panel, but it has no handles and dragging on it moves the view, exactly as dragging on empty space does, so it cannot be knocked out of place while panning. `L` locks or unlocks the selected room. Everything belonging to a locked room is held in place with it: a door or opening in one of its walls, and a fixture or staircase whose middle is in it (for stairs, the point halfway along them, where the round button sits). Each can still be selected and changed in the side panel, which says which room is holding it, but it has no handles and dragging on it moves the view until the room is unlocked. With nothing selected, *Lock every room on this sheet* locks or unlocks them all at once.
- **Side panel:** the panel on the right has three tabs. *Details* shows the house and the current sheet, or the room, door, stairs or fixture that is selected. *Photos* shows the selected photo marker above the photos waiting to be placed. *Issues* shows the selected issue above the totals and the list of issues. Selecting something on the plan brings its tab forward.
- **Sheet tabs:** the tabs run Exterior, then the floors from the main floor up, then *+ Floor*, then the basement if there is one, with *House* and *Issues* set apart at the far end. *+ Floor* adds the next floor up and names it in sequence, *2nd floor*, *3rd floor* and so on, without counting the basement; rename it in the side panel. A floor's side panel has *This sheet is a basement* to mark or unmark one; marking a second sheet while one is already marked asks you to confirm that the house has more than one level below ground.
- **Changing sheets:** going from one floor to another keeps the view where it is, on the same part of the house at the same zoom, since every sheet uses the same measurements. The exterior sheet and the floors each return to the view they were last left at; the first visit shows the whole sheet. *Fit to view* shows everything on the current sheet.
- **Moving the view:** drag empty space or a locked shape to pan, and scroll to zoom. While you are dragging anything (drawing a rectangle, moving or resizing a room, moving a fixture), holding the pointer at the edge of the plan scrolls the view that way, faster the further out it goes, so a room can be drawn past what was on screen when you started. The wheel also zooms part way through a drag, the arrow keys move the view by a tenth of its width, and dragging with the middle mouse button pans in any tool, including between the corners of a polygon.
- **Shapes:** *Rectangle* drags out a box (hold Shift for a square). *Polygon* places a corner per click; hold Shift to keep the side level or upright, click the first corner again or press Enter to close it, and Backspace removes the last corner. Shift while dragging a corner of a finished polygon squares it up with the corners on either side. Select a shape to move it, drag its corners (a rectangle has a handle on each corner, and the opposite corner stays put), drag the bar in the middle of a level or upright wall to move that whole wall in or out without changing the angles, type exact sizes, or rename it. *Combine with touching shapes* joins the selected shape with every shape that overlaps it or shares an edge with it into one outline, so a footprint can be blocked out as a few rectangles and polygons and then merged. Square-cornered shapes with edges within a foot of each other are pulled onto the same line first. Area is calculated per shape and per floor, and the side panel also gives the *Total House Area*: the rooms on every floor above ground, plus the basement rooms marked as finished, leaving out the exterior footprint and separate structures. On a basement sheet each room has a *Finished basement* box. Tick it for finished, heated living space; a ticked room is labelled `finished` and counts toward the total, while an unfinished one, such as storage or a utility room, does not. The basement's own side panel shows its whole floor area and how much of it is finished. Tick *Separate structure* on a shape such as a carport, shed or deck to keep it out of the total and out of *Combine*; it is drawn with a dashed grey line and labelled "not counted".
- **Curved walls:** a wall can bend through one or more *curve points*, shown as yellow handles on a selected shape. There are three ways to make one. While drawing with *Polygon*, Ctrl-click instead of clicking and the wall curves through that point; the outline being drawn shows the curve as you go. On a finished shape, rectangle or polygon, press *Bend a wall…*, then press on a wall and drag: a curve point is added where you let go, and the wall becomes an even arc through it. Or double-click a sharp corner of a polygon to make the wall curve through it. Add more curve points along a wall for a longer or tighter curve; points spaced round a circle give a round room. Double-click a curve point to take it out, which straightens a wall that was bent. The curve is a spline: it runs smoothly through each curve point and meets a sharp corner at an angle. **Areas follow the curves**: a room's square footage, the floor total and a closet's combined area all include a bay and leave out a scooped corner, worked out by cutting each curved wall into 16 short straight pieces, which is well within a square foot for any room. A selected shape shows a curved wall's length along the curve, marked `curved`. A curve point is placed to the quarter inch. Curved walls have limits: a door cannot be placed in one, *Set one wall's length…* does not apply to one, rooms do not catch a wall's thickness from one, and *Combine* turns one into its short straight pieces.
- **Photos:** add photos with *Add photos…*, by dropping them on the Photos panel, or by copying them into `photos/unprocessed/` and pressing *Refresh*. *Refresh* also looks in `photos/processed/` for photos that no marker on the plan holds, as when a photos folder is copied in from another project, and offers to move them to `photos/unprocessed/` so they can be placed. Photos chosen from elsewhere on the computer are copied in; the originals are left alone. A photo whose file name is already in `photos/unprocessed/` is not copied in again: a message lists the names that were left out, so picking the same photos twice does not leave duplicates. To put one on the plan, choose the *Photo* tool, click where it was taken and drag toward what it is looking at. That leaves a marker with a red "not ready" sign. With the marker selected, the side panel lists the unprocessed photos; click one to attach it. The file is renamed and moved into its room's folder. Click a marker for a preview, and *Open* for the full image. *Remove photo* puts the file back in `photos/unprocessed/` under its original name and keeps the marker; *Delete marker* removes both. A marker can hold several photos taken from the same spot: with it selected, press *Add another photo here…* and choose from the unprocessed photos, as many times as you like, then *Done adding*. The marker shows how many it holds. Its arrows, one for each photo since each faces its own way, are drawn only while the marker is selected, so that markers left on the plan stay small and do not get in the way of clicking what is under them; a printed sheet shows them all. The preview beside the marker has **<** and **>** buttons to step through them, and the side panel shows them in a row; click one there to look at it, and the round handle then turns that photo's arrow. *Remove this photo* takes just that one off.
- **Photo size:** a photo added with *Add photos…*, or dropped on the Photos panel, is shrunk as it is copied in, to 2400 pixels along its long edge, saved as a JPEG. A 7 MB phone photo comes to well under 1 MB and is still sharp enough to zoom in on a crack or a stain. The file it was copied from is never touched. *File* → *Settings…* changes the size (3200, 2400 or 1600 pixels) or turns shrinking off. A note above the photo grid says what the photos just added came to, such as *Added 12 photos: 84 MB shrunk to 9 MB*. Left as they are: a photo already within the size and under 1.5 MB, one that would not come out smaller, a GIF, a format the browser cannot draw, photos copied into `photos/unprocessed/` by hand, and photos already in a project. A photo saved as a JPEG takes the `.jpg` ending, so `IMG_1.png` becomes `IMG_1.jpg`. A shrunk copy does not carry the camera's own record of when and where the photo was taken; the original still does.
- **Photo files:** apart from that, files are never resized or converted. The photo grid uses small copies made in memory, so full-size phone photos stay quick to browse. Formats the browser cannot draw (RAW, and usually HEIC) show a "No preview" tile but can still be placed and filed.
- **Issues:** choose *Issue* (`I`) and click the spot. The pin goes on the sheet you are on, which stays open, and the issue opens under the *Issues* tab of the side panel. Each issue has a title, category, status, description, *My estimate* (your own rough cost, as a low and a high figure), any number of professional quotes, and any number of linked photos.
- **Issue numbers:** an issue is given the next number when it is made and keeps it for good. Deleting issue 4 leaves a gap; issue 5 stays issue 5 on the plan, in every list, in a printed report and in anything exported, so a number written down or sent to someone goes on meaning the same issue. A duplicated issue gets a number of its own.
- **Issues without a pin:** some things have no one spot: the roof, the wiring, the plumbing, radon, damp through a whole basement. *Add issue without a pin…*, at the top of the Issues panel and of the Issues sheet, asks whether it is about the whole house or the whole of one floor. It is listed, counted, printed and exported like any other, as *Whole house* or *All of Basement*. *Applies to*, under an issue's title, changes what any issue is about; choosing *One spot* there lets you click the place on the plan to give it a pin, and choosing a whole floor or the whole house takes a pin away. A pin on a floor that is in no room and in no wall gets a note under *Applies to* asking whether it stands for the whole floor; nothing is changed unless you choose it. A pin out in the open on the exterior sheet gets no such note, since the yard, the driveway and a fence are real places; for the outside of the house in general, choose *The whole of Exterior / Site*.
- **Order of work:** *Must be done after*, under an issue's category and status, lists the issues that have to be done before it, such as fixing the roof before the stained ceiling under it. Add one from the list under it and take one off with its ×. An issue that already waits for this one, directly or through others, is not offered, so the order can never go round in a circle. The issue waited for says *Waiting for this one* with the others' numbers. The Issues sheet shows *After #1* on a card, and the printed report, the CSV and the export for AI give the order too. Deleting an issue takes it off every other issue's list. For an order that is not about another issue, such as *before winter*, use *Work that has to happen in a set order* under *Goals and limits*.
- **Not priced:** leave both boxes of *My estimate* empty for an issue you have no figure for. It is shown as *not priced* and adds nothing to the totals, which say how many such issues they cover; that is kept apart from an estimate of $0. With one box filled in, that figure stands for both. *This estimate is* records whether the figure is your own guess or one an AI assistant gave you; a contractor's figure belongs under *Professional quotes*.
- **More about this:** folded under an issue's description are five questions a tradesperson or an AI assistant asks first: when it started, how often it happens, whether it is getting worse, what has been tried, and who would do the work. The answers are printed in the issue report, exported, and searched by *Find*.
- **Rooms with the same name:** a room whose name another room on the same sheet already has shows a note under its name, since their photos would share a folder and lists could not tell them apart. *Link a photo marker…* links a marker that is already on the plan; *New photo here* places a marker beside the issue, links it, and lets you choose its photo. Unlinking leaves the marker in place. A photo marker that is linked to an issue says so in its side panel, above its note, with the issue's number and title and a *Go to issue* button that selects the issue.
- **Professional quotes:** under *My estimate*, *Add professional quote* adds a quote from a contractor or tradesperson to the issue; an issue can have several. Each has the company, contact person, phone, email, address or website, quote or order number, license or insurance number, date, valid-until date, amount, deposit required, start and duration, warranty, a decision (*Received*, *Accepted* or *Declined*), what is included, and notes. *Attach file…* copies the quote itself, a PDF, scan or photo, into the project's `quotes` folder, and *Open file* shows it in a new tab. Each quote folds down to one line with its company and amount. Removing a quote, or deleting an issue that has quote files, deletes those files after a confirmation. Setting a quote's decision to *Accepted* makes its amount the cost of the issue: it replaces *My estimate* in the totals in the side panel, on the Issues sheet and in the printed report, as a single figure with no range, and a note under the estimate says so. Two accepted quotes on one issue, as where a repair needs two trades, are added together. The estimate itself is kept, and counts again if the quote is set back to *Received* or *Declined*. Quotes are shown on the Issues sheet, in the printed report and in the CSV, which has a column for the accepted amount. A duplicated issue does not take the quotes with it.
- **Issues sheet:** the *Issues* tab at the end of the row of sheets shows every issue in the house as one list in the main area, in place of a plan: each with its number, title, sheet, room, category, description, status, cost range and thumbnails of its linked photos. The boxes at the top narrow the list by status, category or sheet, and group it by category, sheet or status, with a count and cost range on each group and a total of what is still to do. Click an issue to read or change it in the side panel; *Show on plan* goes to its pin; a thumbnail opens full size. The drawing tools are out of use while the list shows. Click any sheet's tab to go back to it, at the view you left.
- **Totals:** the Issues panel sums open issues by category, across the house or for one floor.

Renaming a room or floor moves its photos to a folder with the new name. Deleting a room leaves its photos on the floor as unassigned.

## Getting around

- **Zoom:** the mouse wheel zooms at the pointer. The **−** and **+** buttons at the bottom right of the plan, and the `-` and `+` keys, zoom about the middle of the view. The figure between the buttons is the zoom level: 100% is ten pixels to the foot, the point at which the grid squares become 1 ft. Click it to go to 100%. *Fit to view* (or `0`) shows the whole sheet.
- **Find:** type part of a name in the *Find* box at the top (Ctrl+F) to list the rooms, outlines, issues, photo markers, fixtures, stairs and sheets that match, on every sheet. Issues are matched on their number, title, description, category and status; photo markers on their file names, original names and notes; fixtures on their type and note. Click a result, or press Enter for the highlighted one (the arrow keys move the highlight), to go to its sheet with it selected. The view moves only if it has to: it centres on something out of sight and zooms out for something too big to fit.
- **Duplicate:** *Duplicate* in the side panel, or Ctrl+D, copies the selected room, outline, fixture, stairs or issue. The copy is set down just beside the original and selected, ready to drag into place. It keeps the name, size and settings of the original, except that a copy of a locked room is not locked. Doors and photo markers are not duplicated.
- **Shortcut keys:** *Keyboard shortcuts* under the **?** button, or the `?` key, lists every key.
- **Settings:** *File* → *Settings…* holds how the app behaves: whether the getting-started tips are shown in new projects, whether a preview is shown beside a selected photo marker, whether the view scrolls when something is dragged to its edge, and which way the mouse wheel zooms. These are kept in the browser, not in the project, so they apply to every project opened in it. The same window leads to the *House standards* of the open project.
- **About:** *About* under the **?** button, and *About this app* on the start page, gives the version and what the app does with your files: nothing leaves the computer.

## On a phone or tablet

Every tool works with a finger. The layout follows the size of the screen, and the handling of touch follows the finger, so a touchscreen laptop gets the finger handling too.

- **Moving about the plan:** drag with one finger to move the view, and pinch with two to zoom and move it together. A pinch that starts on the plan keeps going if the second finger lands off it, on the side panel or the toolbar. While a finger is on the plan the page itself does not scroll, zoom or pull down to reload, which Safari on an iPad would otherwise do as well. If the browser calls off a touch part way through a rectangle or a photo marker, nothing is made. The − and + buttons still work.
- **Tap, then drag:** a tap acts where the finger landed, so a wobbly fingertip does not shift what it taps. Dragging a room, pin, photo marker, door or fixture that is not selected moves the view instead, so a finger can pan across a busy plan without picking things up: tap it first to select it, then drag it. With a mouse, pressing on anything still drags it straight away.
- **Bigger handles:** on a touch screen the corner and wall handles, the pins and the photo markers are drawn bigger, and the first corner of a polygon catches a tap from further away. Plans print at the usual size.
- **The touch bar:** while a tool is in use, or a room, door or fixture is selected, buttons at the bottom left of the plan stand in for the keys: *Finish shape* (Enter) and *Undo corner* (Backspace) while drawing a polygon, *Cancel* (Esc) to go back to Select, and two switches. *Square* works as holding Shift: a rectangle is drawn square, a polygon side or a measuring line is kept level or upright, and a dragged corner of a polygon is squared up. *Free* works as holding Alt: nothing catches on the grid or on other walls. The switches stay on until the tool changes. To make a wall curve through a corner, tap the corner twice, as a double-click does.
- **One view at a time:** on a phone the plan and the side panel's *Details*, *Photos* and *Issues* tabs each take the whole screen, chosen by the bar along the bottom: *Plan* shows the plan, or the Issues or House sheet if one of those is open. Selecting something on the plan stays on the plan and puts a dot on the button for the view that shows it, so tap a room and then *Details* to change it. Placing a new issue pin or photo marker, and choosing an issue on the Issues sheet, goes straight to its view, as those need filling in; *Plan* goes back. A tablet keeps the panel beside the plan, a little narrower than on a computer.
- **Toolbar:** on a phone the project name and the File menu sit on the top line, and every tool is on one row under it that scrolls sideways. The sheet tabs scroll sideways the same way. On a phone turned on its side, where height is shortest, the toolbar shares the top line with the project name and the hint line under the plan is left out. Key letters are left off the buttons on a touch screen; *Keyboard shortcuts* still lists them.
- **Photos from the camera:** on a phone or tablet, *Take photo…* beside *Add photos…*, on the Photos tab and on an empty photo marker, opens the camera, so photos can be taken on the spot and placed straight away. *Add photos…* picks several from the photo library at once; on Android that picker has no camera in it, hence the separate button. A photo from the camera is named for when it was taken, such as `photo-2026-10-07-143005.jpg`, because an iPhone names every one `image.jpg`. The button is not shown on a computer. A selected photo marker's preview lies across the top or bottom of the plan, away from the marker; tap it to see the photo full size.
- **Tooltips:** the explanations shown when the mouse rests on a button have no touch equivalent; the hint line under the plan and *Tips for this sheet* under **?** say what each tool does.

## Printing and PDF

*File* → *Print or save as PDF…* (or Ctrl+P) asks what to include and then opens the browser's print window; choose *Save as PDF* there as the printer to get a PDF file.

- **Floor plans:** the sheet you are on, or every sheet that has something drawn on it, each on its own landscape page with the house name, address, floor area, grid size and date above it. The exterior sheet shows everything on it, the whole lot; a floor is fitted to its own rooms, so the house fills the page. Photo markers are left off the plans unless *Show photo markers on the plans* is ticked, since the photos themselves are in the issue report. Anything turned off in the *View* menu is left out too. The aerial picture is not printed.
- **Issue report:** a table of open issues by category with low and high cost totals, then every issue with its number, floor, room, category, status, cost range and description, and optionally the photos linked to it. The numbers match the pins on the plans. Issues marked Done can be left out.

## Moving a project

A project is its folder, so copying the whole folder and using *Open project folder* on the copy always works. Inside the app, the *File* menu at the top left holds the exports and imports, and *Close project*, which saves and returns to the start page. There are two kinds of export:

- **Export project (.zip)** downloads everything in one file: the plan, every photo, placed or not, the aerial picture and the quote files. To bring it in, press *New project*, type the house name and address, choose the zip under *Start from an exported project (.zip) or a plan file*, and pick an empty folder. The photos are unpacked to where the plan expects them, so every marker, room and issue link comes across. The name and address typed there are used for the new project, in place of the ones in the file. A zip of a whole project folder made outside the app works the same way.
- **Export plan only** downloads the plan file alone, and *Import plan…* replaces the open project's plan with one. A plan file carries no photos. If an imported plan refers to pictures that are not in the project's folder, a message says how many and which, and how to bring them across.

*Export issues (CSV)* produces a spreadsheet of the issue list, with each issue's room and where it is in words.

## The House sheet

The *House* tab, beside *Issues* at the end of the row of sheets, holds what is known about the house as a whole, in place of a plan. It is saved as you type.

- **House facts:** the year built, the foundation and what the basement walls are made of, outside walls, roof and when it was last replaced, the supply and drain pipes, the electrical service, panel and wiring, the heating, cooling and water heater with the year each was put in, sewer or septic, city water or a well, which way north is, and what has happened to the house: storms, floods, fires, big repairs. Choose *Don't know* where you do not know. An answer that leaves something out, *More than one kind*, *Partial basement*, *Both* or *Something else*, brings a box beside it to say which and where, such as *basement under the main house, slab under the garage*; it goes into the export after the answer.
- **Goals and limits:** whether you are staying or selling, any dates things have to be done by, what you can do yourself, and work that has to happen in a set order. A *Money* box holds the budget and other money matters, kept apart from the rest.
- **Household:** who lives in the house: how many adults and children and roughly how old, anyone who finds stairs, steps or a bathtub hard, health the house can affect (asthma, allergies, anyone more at risk from mould, radon, lead or carbon monoxide), pets, and changes coming. It decides what matters most, such as a walk-in shower or how urgent damp is. Being private, it is kept apart like the money box and left out of the export for AI unless you tick the box for it.
- **Walkthrough checklist:** sixteen lines covering what every house has, from the roof and gutters to radon and hazardous materials, each marked *Fine*, *Issue* or *Don't know*, with a note. Marking a line *Issue* offers to add an issue for it, about the whole house and without a pin; the line then shows that issue with a *Go to issue* button. An issue already made, such as a roof issue pinned on the plan, can be linked to its line instead, with *or link one already made…* beside *Add an issue*; *Unlink* takes the link off and leaves the issue as it is. The export for AI gives each line's issue by number, so a line with an issue linked no longer reads as not looked at.

## Asking an AI about the house

*File* → *Export for AI (.zip)…* makes one zip to hand to an AI assistant such as Claude or ChatGPT, so it can look over the house and its issues with you. Nothing is sent anywhere by the app: the zip is saved to your computer and you choose what to do with it. Unzip it and upload the files, or the whole folder, to the assistant.

```
README-FIRST.md               the brief: the house and every issue in plain words
issues.csv                    the same issues as a table
plans/main-floor.png          a picture of each sheet, with the numbered issue pins
plans/aerial.jpg              the aerial picture of the lot, if one has been added
photos/issue-05-photo-1.jpg   small copies of each issue's photos, named after the issue
```

- **The brief** opens with how to read it (units, directions, what the categories mean) and a request you can paste in. It then lists each floor's rooms with their sizes and fixtures (fixtures of one kind counted together, such as *3 counters or islands*, unless one has a note of its own), the house facts, your goals, the walkthrough checklist, the totals, and every issue. Facts and checklist lines you have not answered are listed as such, since they tell the assistant what to ask about. An issue's follow-up questions (when it started, how often, whether it is getting worse, what has been tried, who would do the work) are listed only where answered; the rest are named together on one line, or as *none answered*. The budget and money boxes under *Goals and limits* are left out unless you tick the box for them.
- **Where each issue is, in words:** its sheet and room, the nearest wall and how far from it, and any fixture or stairs within 4 ft, such as *Main floor: Kitchen; 2' from the north wall; at the kitchen sink*. Then what is at the same spot on every other floor, such as *Above, on 2nd floor: Bathroom; at the bathtub*, which is what matters most for a leak. A pin in a wall, which is the gap between rooms since rooms are drawn as the clear space inside their walls, is said by that wall: *in the wall between Kitchen and Living room*, or *in the north wall of Kitchen* for an outside wall; a pin counts as in a wall within 1 ft of a room, and the Issues sheet and the CSV give the nearer room for it. A floor sheet with nothing drawn on it is left out of these lines, so an empty sheet for a floor the house does not have does not turn up as *no room is drawn* under every issue. An issue pinned on the exterior sheet over the house lists the room under it on each floor.
- **North:** set *North is toward* under the house's address in the side panel, to the side of the plan north points to. Walls and photo directions are then given as north, south, east and west. Until it is set they are given by the plan itself, top, bottom, left and right, and the brief says so.
- **Costs:** each issue gives the figure that counts, the accepted quote or your own estimate, exactly as the Issues sheet totals it, then every quote with its amount, decision, dates (a quote past its valid-until date is marked expired), deposit, warranty and what it includes. An issue with no estimate and no accepted quote reads *not priced*.
- **Plan pictures:** each sheet is framed to take in every issue pin on it as well as what is drawn, so a pin out in the yard is not cut off. Printed plans are framed the same way.
- **Photos:** every photo on every marker linked to an issue, 1600 pixels on the long edge, each with the room it was taken in and the way it faces. Pictures the browser cannot draw (RAW, usually HEIC) are left out and named in the brief.
- **Aerial picture:** a small copy of the aerial picture on the exterior sheet, if there is one, so the assistant can see the yard, driveway, streets and neighbours that are not drawn. Its top is the top of the plan pictures.
- **Choices when exporting:** leave out the pictures of the sheets, or the aerial picture; include issues marked Done; include photos not linked to an issue (under `photos/other/`); include the quote files; include contractors' contact details, which are otherwise left out; include your budget and money matters; include the Household box. The last three are private and are off unless ticked.

## Plan file format

`plan.housemap.json`, version 5. **Every length and position is in inches**, x to the right and y down, so 15' 6" is `186`. Values are kept to the nearest quarter of an inch. Inside the app you only ever see and type feet and inches.

Version 1 and 2 files, which used decimal feet, are converted when opened and saved back as version 5. A file is read as inches only if its `version` is 3 or higher. Version 4 changed only `items`: a version 3 file's items, whose boxes were the space they took up on the sheet, are converted when opened. Version 5 changed only the meaning of an issue's `costLow` and `costHigh` both being `0`: earlier versions could save that for an issue nobody had priced, so in an older file it is read as no estimate (`null`), while from version 5 on it is an estimate of $0 that was typed in.

```json
{
  "version": 5,
  "units": "inches",
  "name": "Maple Street house",
  "address": "",
  "north": 0,
  "exteriorSized": true,
  "tipsSeen": { "exterior": true },
  "facts": { "built": 1962, "foundation": "Full basement", "roofYear": 2005, "wiring": "Don’t know" },
  "goals": { "plan": "Staying for many years", "diy": "Painting, simple plumbing", "money": { "budget": "$15,000 this year" } },
  "checklist": { "roof": { "state": "issue", "note": "curling on the south side", "issueId": "i2" }, "radon": { "state": "unknown" } },
  "standards": { "exteriorWall": 6, "interiorWall": 4.5, "door": 30, "opening": 32, "exteriorDoor": 36, "ceiling": 96 },
  "floors": [
    {
      "id": "f1", "name": "Exterior / Site", "kind": "exterior",
      "rooms": [
        { "id": "r1", "name": "House outline", "points": [{ "x": 0, "y": 0 }, { "x": 480, "y": 0 }, { "x": 480, "y": 336 }, { "x": 0, "y": 336 }] },

      ]
    },
    {
      "id": "f2", "name": "Main floor", "kind": "floor",
      "rooms": [
        { "id": "r2", "name": "Kitchen", "x": 6, "y": 6, "w": 146, "h": 168 },
        { "id": "r3", "name": "Family room", "x": 156.5, "y": 6, "w": 180, "h": 168, "level": -8 }
      ],
      "openings": [
        { "id": "d1", "kind": "opening", "along": "y", "x": 154.25, "y": 90, "w": 32, "t": 4.5, "hinge": 0, "swing": 0 },

  "nextIssueNum": 3,

    { "id": "p1", "floorId": "f2", "roomId": "r2", "x": 74, "y": 85, "dir": 90, "file": "photos/processed/main-floor/kitchen/kitchen-01.jpg", "original": "IMG_0412.jpg", "note": "" }

- **north:** optional. The way north points on the sheets, in degrees clockwise from the top: `0` for the top of the plan, `90` for the right, in steps of 45. Leave it out, or use `null`, if it is not known. It is only used to put directions into words in the export for AI.
- **facts:** optional; what is known about the house as a whole. Years are numbers (`built`, `roofYear`, `heatingYear`, `coolingYear`, `waterHeaterYear`). The rest are words, as chosen in the app or typed: `foundation`, `basementWalls`, `walls`, `roof`, `supply` and `drains` (pipes), `service`, `panel` and `wiring` (electrical), `heating`, `cooling`, `waterHeater`, `sewer`, `water`, and the free-text `events` and `other`. Leave out what is not known, or use `"Don’t know"`. Any of these may have a free-text companion with `Detail` on the end of its key, such as `foundationDetail`, saying which and where for an answer such as `"More than one kind"`.
- **goals:** optional. `plan`, `timeline`, `diy`, `order` and `notes` are words; `money` holds `budget` and `notes`, which are left out of the export for AI unless asked for.
- **issues** may also hold `after`: the `id`s of the issues that must be done before this one.
- **household:** optional. `people`, `mobility`, `health`, `pets` and `changes` are words, left out of the export for AI unless asked for.
- **checklist:** optional; the walkthrough. Each key is one line (`roof`, `gutters`, `grading`, `foundation`, `siding`, `windows`, `attic`, `plumbing`, `waterHeater`, `electrical`, `hvac`, `alarms`, `pests`, `radon`, `hazards`, `outside`) with a `state` of `fine`, `issue` or `unknown`, an optional `note`, and an optional `issueId`, the `id` of the issue added for it.
- **units:** always `"inches"`. It is there for people reading the file; the app goes by `version`.
- **floors:** exactly one sheet has `kind: "exterior"`; the rest are `"floor"`. List the floors from the lowest up, a basement first: stairs use this order to tell up from down. An optional `"basement": true` on a floor marks it as a basement: its tab is shown last, after *+ Floor*, and it is not counted when a new floor is named. A file without the mark on any floor has it added to a floor named `Basement`.
- **rooms:** a rectangle has `x`, `y`, `w`, `h`. A polygon has `points` instead (three or more corners, in order). A point with `"curve": true`, as in `{ "x": 60, "y": -24, "curve": true }`, is one the wall curves through instead of a sharp corner: the walls on either side of it are drawn as a smooth curve passing through it, and the room's area follows the curve. A wall between two points without it is straight. Three points in a row along a bay, the middle one marked, give an arc; mark every point of a polygon for a rounded shape. An optional `"separate": true` marks a structure that is not part of the house (carport, shed): it is left out of area totals and is never combined with other shapes. On a floor, a room is the clear inside space, so neighbouring rooms sit a wall's thickness apart. An optional `level` is how far the room's floor sits above (positive) or below (negative) the rest of its sheet: `-8` is a room 8" down. An optional `"finished": true` on a room of a basement floor marks finished living space, which counts toward the total house area; other basement rooms do not. An optional `"locked": true` keeps the shape from being dragged or reshaped on the plan. An optional `partOf` is the `id` of the room on the same floor that this one belongs to, as a closet to its bedroom.
- **openings:** the doors and open doorways on a floor; leave it out or use `[]` for none. `kind` is `door`, `opening` (a doorway with no door), `exterior`, `bifold`, `sliding` (a pair of sliding panels), `open` (no wall at all along this stretch) or `half` (a half wall). `x`, `y` is the centre of the opening, in the middle of the wall's thickness. `along` is the direction the wall runs: `"x"` across the sheet, `"y"` up and down. `w` is the width of the opening and `t` the thickness of the wall there, `0` where two rooms meet edge to edge. `hinge` is the end the hinges are on (`0` left or top, `1` right or bottom) and `swing` the side the door opens into (`0` above or left of the wall, `1` below or right); `hinge` only matters for `door` and `exterior`, and `swing` for those and `bifold`.
- **items:** the fixtures, appliances and stairs on a floor; leave it out or use `[]` for none. `note` is free text on either.
  - A fixture has `kind`: `toilet`, `sink` (bathroom), `tub`, `shower`, `ksink` (kitchen sink), `counter`, `stove`, `fridge`, `dishwasher`, `washer`, `dryer`, `wh` (water heater) or `furnace`; an empty string is one whose type has not been chosen yet. `x`, `y`, `w`, `h` is its box before it is turned: `w` across it and `h` from its back, the side against the wall, to its front, with the back at the top. `rot` then turns that box clockwise about its middle, by any number of degrees. A stove 30" wide and 26" deep that backs onto the right-hand wall has `"w": 30, "h": 26, "rot": 90`, and its middle is at `x + w/2`, `y + h/2`.
  - Stairs have `"kind": "stairs"` and no box. `points` is a path down the middle of the stairs from the end you step on to the far end, with one point at each change of direction (two points for a straight flight), and `w` is the width of the stairs. A landing `w` square is drawn at each turn. `dir` is `up` or `down` from this floor, and `to` is the `id` of the floor they lead to, or `""`. The same stairs on the other floor have the same `points` in the opposite order, the opposite `dir`, and `to` pointing back.
- **standards:** the house's usual sizes: `exteriorWall` and `interiorWall` thickness, `door`, `opening` and `exteriorDoor` width, and `ceiling` height. Leave the whole entry out to have the app ask for them the first time a floor is opened.
- **issues:** `category` is one of `safety`, `major`, `minor`, `cosmetic`, `preference`; `status` is `Open`, `In progress` or `Done`. `num` is the issue's number, which never changes and is never given to another issue; `nextIssueNum` on the plan is the number the next new issue gets. Leave both out of a hand-written file and the issues are numbered in the order they are listed. `x` and `y` are `null` for an issue about a whole floor, and `floorId` is `null` as well for one about the whole house. `costLow` and `costHigh` are the owner's own estimate, in dollars, or `null` where there is none; in a file whose issues have no `num`, a pair of zeros is read as no estimate. An optional `costSource` of `"ai"` marks an estimate that came from an AI assistant. Optional `started`, `frequency` and `tried` are free text; `worse` is `yes`, `no` or `unknown`; `who` is `me`, `pro` or `unsure`. `photoIds` lists the `id`s of linked entries in `photos`. An optional `quotes` is a list of professional quotes, each `{ "id", "company", "contact", "phone", "email", "address", "number", "license", "date", "validUntil", "amount", "deposit", "timeline", "warranty", "status", "scope", "notes", "doc", "original" }`; every field but `id` is optional, dates are `YYYY-MM-DD`, `status` is `Received`, `Accepted` or `Declined`, and `doc` is the path of the quote's file in the project folder, such as `quotes/acme-plumbing.pdf`. `photo` is an optional free-text note kept from version 1 files.
- **exteriorSized:** whether the exterior outline has been confirmed as true to size. While it is `false`, floors show a warning. A file without it is treated as `true` if it has rooms but no exterior shapes, otherwise `false`.
- **tipsSeen:** which getting-started tips this project has already shown, such as `{ "exterior": true }`. Leave it out, or use `{}`, to have them shown.
- **aerial:** `null`, or the picture drawn under the exterior sheet. `x`, `y` is its top-left corner and `w` its width; `aspect` is its height divided by its width; `show` is whether it is drawn under the grid.
- **photos:** each entry is a marker. A marker that holds more than one photo has `more`: a list of the others, each `{ "id", "dir", "file", "original" }` with its own direction, all taken from the marker's `x`, `y` and filed under its room. `x`, `y` is where the photographer stood; `dir` is the direction they faced in degrees clockwise from the top of the plan (0 up, 90 right). `roomId` is `null` when the photo is not in a room. `file` is the path inside the project folder and `original` is the file name it arrived with; both are empty strings for a marker that has no photo attached yet.

js/landing.js     start page and new project wizard
js/main.js        toolbar, keyboard and start-up
```

The scripts are plain files loaded in that order, so the page still works when opened straight from disk. A new script has to be added to the list in `js/load.js` and to the one in `sw.js`. The page's security policy does not run scripts or `onclick` attributes written into `index.html`; put code in a file and use `addEventListener`.

## Accuracy

Everything in this app is approximate. The plans are for planning repairs and keeping track of a house; they are not professional architectural drawings or a survey, and should not be relied on for construction, permits, or anything legal or financial.

Early working version. The first test case is a 1962 house, whose plan file is kept privately.
